# Telegram-бот «Для рішучих»

Бот продає курс через персональну пропозицію, яка діє 24 години від першого `/start`:
офер із живим таймером → «Обрати пакет» → опис пакета → посилання на оплату.
Протягом 24 годин бот нагадує про пропозицію і пише, скільки часу залишилось; потім пропозиція згорає.
Оплата не перевіряється — доступ до курсу менеджер видає вручну.

> **Почніть тут:** [`KROK_ZA_KROKOM.md`](KROK_ZA_KROKOM.md) — що зробити, щоб запустити бота, крок за кроком.
>
> **Зараз (з 9 листопада 2026) бот працює цілодобово на Railway** — як це влаштовано і як оновлювати:
> [`DEPLOY.md`](DEPLOY.md) → «Як розміщено зараз».

## Що вміє

* **`/start`** фіксує час першого запуску і запускає **персональний таймер на 24 години**.
  Надсилає офер із таймером, текстом «Пропозиція для рішучих. Діє 24 години» і кнопкою **«Обрати пакет»**.
  Таймер — **живий відлік** «⏳ 23:59:55» зі смужкою залишку часу 🟩🟩🟩🟩🟩🟩🟩⬜️⬜️⬜️: поки людина в чаті,
  секунди біжать (оновлення кожні 5 с), інакше таймер оновлюється раз на хвилину. Він — окремим коротким
  повідомленням під офером, тож сам офер не редагується і «шторки» в ньому не згортаються.
* **Повторний `/start` таймер не перезапускає**: приходить той самий офер із поточним залишком часу.
* **Пакети**: список із назвою і ціною → розширений опис → кнопки **«Отримати посилання на оплату»**
  і **«Подивитися інші пакети»** → посилання на оплату саме цього пакета (+ кнопка «Перейти до оплати»).
  Пакет без посилання на оплату — інформаційний: під описом лише «Подивитися інші пакети» (так зараз).
  У кожного пакета може бути **картинка**: тоді опис приходить підписом під фото.
* **Нагадування** за розкладом із конфігурації, із залишком часу. У «тихі години» (22:00–08:00) — без звуку.
* **Подарунок за швидке рішення:** під таймером — заклик «Встигни забрати курс у подарунок!» і кнопка
  «🎁 Що за подарунок?» з описом подарунка (`messages.gift`). Після 24 год подарунок «згорає», кнопка зникає.
* **«📖 Інформація про курс»** — кнопка під таймером, у списку пакетів, під кожним пакетом, під нагадуваннями й
  описом подарунка: бот ще раз надсилає опис курсу (текст оферу), щоб не гортати чат угору.
* **Через 24 години** нагадування припиняються, таймер в офері показує «час вийшов», а під ним лишається
  тільки «📖 Інформація про курс». На `/start`, кнопки зі старих повідомлень і будь-які повідомлення бот
  надсилає опис курсу, вже без таймера й подарунка (`messages.expired: ""`), або свій текст у `messages.expired`.
  Можна натомість продовжити продаж за звичайною ціною (`packages_after_expiry: true`).
* **Усе редагується в одному файлі** [`content.yaml`](content.yaml): тексти, назви й ціни пакетів, описи,
  посилання на оплату, тексти й розклад нагадувань, назви кнопок і їх порядок.
* **Переживає перезапуск сервера**: стан у базі SQLite на постійному диску; таймери й нагадування продовжуються.
* Додатково (необов'язково): сповіщення менеджеру про кожен запит посилання на оплату, `/stats` для
  адміністраторів, `/myid`, джерела трафіку через посилання `t.me/ваш_бот?start=instagram`.

## Запуск на комп'ютері (Windows)

Для цілодобової роботи бот розміщують на хостингу ([`DEPLOY.md`](DEPLOY.md)); на комп'ютері він працює, поки
відкрите вікно запуску і комп'ютер не спить.

1. Встановіть **Python 3.14 або 3.13** з python.org/downloads/windows → «Windows installer (64-bit)».
   У встановлювачі поставте галочку **Add python.exe to PATH**.
   ⚠️ **Python 3.15 поки не підходить**: бібліотека aiogram його ще не підтримує.
2. Двічі клацніть **`start_bot.bat`** у папці проєкту. Якщо Windows попередить про невідомий файл —
   «Докладніше» → «Виконати все одно».
   * Перший запуск сам створить середовище Python і встановить бібліотеки (1–2 хв).
   * Потім відкриється Блокнот із файлом `.env`: вставте токен бота одразу після `BOT_TOKEN=`,
     збережіть (`Ctrl+S`) і закрийте Блокнот — бот запуститься.
3. Відкрийте бота в Telegram і натисніть **Start**.
4. Зупинити бота — `Ctrl+C` або просто закрити вікно. Наступні запуски — знову подвійним кліком по `start_bot.bat`.

* Перевірити `content.yaml` без запуску бота — подвійний клік по **`check_content.bat`**.
* Середовище Python і база для локального запуску лежать **поза OneDrive**: `%LOCALAPPDATA%\TgBotDlyaRishuchih`
  (вставте цей шлях в адресний рядок Провідника). Щоб пройти воронку «з нуля» (таймер для вашого акаунта
  запускається лише один раз), зупиніть бота і видаліть там файл `bot.db` (і `bot.db-wal`, `bot.db-shm`, якщо є).
* Не запускайте на комп'ютері той самий токен, що вже працює на хостингу (зараз — на Railway): дві копії бота
  конфліктують — одна не отримує повідомлень, а нагадування й таймери дублюються.

## Як редагувати контент

1. Відкрийте [`content.yaml`](content.yaml) у будь-якому текстовому редакторі (Блокнот, VS Code) або прямо
   на GitHub (✏️ **Edit**). Підказки — у коментарях у самому файлі; місця, які треба замінити, позначено ✏️.
2. Перевірте файл: подвійний клік по `check_content.bat` (покаже помилки з назвою поля і підсумок:
   пакети, розклад нагадувань).
3. Перезапустіть бота. На Railway зміни заливає Claude: commit → `python scripts/railway_deploy.py`
   (потрапляє лише закомічене). Якщо у файлі помилка, нова версія не запуститься, і продовжить працювати попередня.

Що саме де лежить:

| Що змінити | Де в `content.yaml` |
|---|---|
| Текст оферу | `messages.offer` |
| Повідомлення з таймером і кнопкою під офером | `messages.offer_timer` (порожнє — таймер у самому офері) |
| Рядок таймера / «час вийшов» | `messages.timer`, `messages.timer_expired` (відлік — `{countdown}`, смужка — `{progress}`) |
| Живий відлік: як часто оновлювати, формат, смужка | `settings.timer_fast_every`, `timer_fast_for`, `timer_update_every`, `countdown_format`, `progress_length`, `progress_full`, `progress_empty` |
| «Шторки» (згорнуті цитати), спойлери, жирний… | теги в будь-якому тексті: `<blockquote expandable>…</blockquote>`, `<tg-spoiler>…</tg-spoiler>`, `<b>…</b>` (шпаргалка — на початку `content.yaml`) |
| Назви, ціни, описи, посилання на оплату | `packages` (порядок у файлі = порядок кнопок) |
| Картинки пакетів | файли в папці `images`, у пакеті — рядок `image: "images/start.jpg"` |
| Кнопка «📖 Інформація про курс»: що надсилає і де показується | `messages.course_info` (порожньо — повторюється текст оферу), `buttons.course_info`, `keyboards` (у списку пакетів — `keyboards.packages_list`) |
| Текст повідомлення з посиланням на оплату | `messages.payment` |
| Що бот відповідає після завершення 24 годин | `messages.expired` (порожньо — опис курсу, як «📖 Інформація про курс») |
| Тексти й розклад нагадувань | `reminders` (`after` — від старту, `before_end` — до кінця) |
| Назви кнопок | `buttons` |
| Порядок і розміщення кнопок | `keyboards` |
| Тривалість пропозиції, часовий пояс, тихі години, продаж після 24 год | `settings` |

## Команди бота

| Команда | Для кого | Що робить |
|---|---|---|
| `/start` | усі | Офер із таймером (перший раз — запускає таймер) |
| `/myid` | усі | Показує id людини або групи — для `MANAGER_CHAT_ID` і `ADMIN_IDS` |
| `/preview` | адміністратори (`ADMIN_IDS`) | Показує всі нагадування, опис подарунка і повідомлення про завершення — так, як їх побачать люди |
| `/stats` | адміністратори (`ADMIN_IDS`) | Користувачі, активні/завершені пропозиції, перегляди пакетів, запити посилань, джерела |

## Налаштування (змінні середовища)

Локально — у файлі `.env`, на хостингу — у Variables. Тексти тут не задаються: вони в `content.yaml`.

| Змінна | Обов'язкова | Опис |
|---|---|---|
| `BOT_TOKEN` | так | Токен від @BotFather |
| `MANAGER_CHAT_ID` | ні | Куди надсилати сповіщення «💳 Запит посилання на оплату» |
| `ADMIN_IDS` | ні | Id адміністраторів через кому (доступ до `/stats`) |
| `DB_PATH` | ні | Файл бази. За замовчуванням `data/bot.db`; на Railway — автоматично на Volume |
| `CONTENT_PATH` | ні | Інший файл контенту замість `content.yaml` |
| `LOG_LEVEL` | ні | `INFO` (за замовчуванням) або `DEBUG` |

## Структура проєкту

```
content.yaml           ← увесь контент (тексти, пакети, ціни, посилання, нагадування, кнопки)
images/                ← картинки пакетів
start_bot.bat          ← запуск на Windows подвійним кліком
check_content.bat      ← перевірка content.yaml подвійним кліком
.env.example           ← зразок налаштувань (start_bot.bat сам створить із нього .env)
bot/
  __main__.py          запуск: python -m bot
  app.py               збирання і запуск бота
  config.py            змінні середовища
  content.py           завантаження і перевірка content.yaml
  check_content.py     python -m bot.check_content
  texts.py             тексти і кнопки для конкретного користувача
  funnel.py            логіка воронки: старт, пакети, оплата, нагадування, завершення
  handlers.py          обробка натискань і повідомлень
  admin.py             /myid, /stats
  scheduler.py         фонові нагадування, живий таймер, завершення пропозиції
  storage.py           база даних SQLite
  sender.py            безпечне надсилання в Telegram
  timeutils.py, htmltext.py, paths.py
tests/                 автотести (фейковий Telegram, без мережі; власний еталонний контент tests/fixtures/content.yaml)
scripts/e2e_restart_check.py   перевірка справжнього процесу з перезапуском
scripts/railway_deploy.py      оновлення бота на Railway: заливає закомічений код, показує журнал
Dockerfile, docker-compose.yml для хостингу
```

## Розробка і перевірка

```bash
python -m pip install -r requirements-dev.txt
```
```bash
python -m pytest
```

* `python -m pytest` — 278 автотестів: контент, формати часу, база даних, усі сценарії користувача через
  справжній диспетчер aiogram із фейковим Telegram, планувальник із керованим часом, перезапуск.
  Тести працюють на власному еталонному контенті (`tests/fixtures/content.yaml`), тож зміни в `content.yaml`
  їх не ламають; щодо справжнього `content.yaml` перевіряється лише, що він коректний.
* `python scripts/e2e_restart_check.py` (Linux/macOS) — справжній процес бота проти локального фейкового
  Telegram: пропозиція скорочена до 90 с, бот перезапускається посеред таймера (≈ 2 хв).
  З `--docker ІМ'Я_ОБРАЗУ` — те саме для Docker-образу, як на Railway.
* Правила розробки для наступних сесій — [`CLAUDE.md`](CLAUDE.md).
