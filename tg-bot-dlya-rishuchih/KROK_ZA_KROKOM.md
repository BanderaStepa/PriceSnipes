# Що зробити, щоб запустити бота — крок за кроком

Повний шлях від архіву до бота, що працює цілодобово. Разом ≈ 1,5–2 години, з них більшість — тексти.
Ставте галочки (`[x]`) по ходу. Подробиці для кроків 4–9 — у [`DEPLOY.md`](DEPLOY.md).

---

## Що підготувати заздалегідь

- [ ] **Текст оферу** — те, що людина бачить після `/start`.
- [ ] **Пакети**: для кожного — назва, ціна, опис (що входить, бонуси).
- [ ] **Посилання на оплату для кожного пакета.** Створіть їх у своїй платіжній системі (WayForPay, LiqPay,
      monobank тощо): окреме посилання з потрібною сумою на кожен пакет.
- [ ] **Контакт менеджера** в Telegram (наприклад, `@manager`) — йому люди надсилатимуть квитанції.
- [ ] **Банківська картка** — для хостингу Railway ($5 на місяць).

## Крок 2. Впишіть свій контент у `content.yaml` (20–40 хв)

- [ ] Відкрийте `content.yaml`: правою кнопкою → **«Відкрити за допомогою»** → **Блокнот**
      (зручніше — безкоштовні Notepad++ або VS Code: вони підсвічують структуру).
- [ ] Натисніть `Ctrl+F` і шукайте `✏️` — так позначено всі місця, які треба замінити.

**а) Офер** — розділ `messages` → `offer`. Замініть абзац «✏️ Тут буде текст оферу…» своїм текстом.
Рядки «🔥 Пропозиція для рішучих. Діє 24 години» і `{timer}` (на його місці бот показує таймер) — залиште:

```yaml
  offer: |
    Привіт, {first_name}! 👋

    Ваш текст оферу. Кілька абзаців — через порожній рядок.

    🔥 <b>Пропозиція для рішучих. Діє 24 години</b>
    {timer}
```

**б) Пакети** — розділ `packages`. Для кожного пакета змініть `name`, `price`, `payment_url` і текст `description`:

```yaml
  - id: start
    name: "Старт"
    price: "2 490 грн"
    payment_url: "https://…ваше-посилання-на-оплату-пакета-Старт…"
    description: |
      <b>Пакет «{name}» — {price}</b>

      Для кого цей пакет, що входить:
      ✅ 12 відеоуроків
      ✅ Доступ на 3 місяці

      🎁 Бонус для рішучих: …
```

- Інша кількість пакетів: щоб **додати** — скопіюйте блок від `- id:` до кінця опису й дайте новий `id`
  латиницею (наприклад, `premium`); щоб **прибрати** — видаліть увесь блок.
- Порядок пакетів у файлі = порядок кнопок у боті.

**в) Контакт менеджера** — у `messages` → `payment`, `expired`, `expired_notice`, `fallback` замініть рядки
«✏️ … @manager» на свої, наприклад: `Квитанцію про оплату надішліть менеджеру: @ваш_менеджер`.

**г) Нагадування** — розділ `reminders`. Перегляньте тексти. Час: `after` — через скільки після `/start`,
`before_end` — за скільки до кінця (зараз: через 2 год, через 12 год, за 3 год і за 1 год до кінця).

**ґ) Що буде після 24 годин** — `settings` → `packages_after_expiry`:
`false` (зараз) — продаж закривається; `true` — пакети продаються й далі. Якщо вибрали `true`, у розділі
`keyboards` замініть рядок `expired: []` на два рядки (щоб під «пропозиція завершилась» була кнопка):

```yaml
  expired:
    - [choose_package]
```

**Правила, щоб не зламати файл:**
- Не натискайте **Tab** — лише пробіли. Новий рядок тексту починайте з такого самого відступу, як сусідні.
- Змінюйте лише текст праворуч від двокрапки або під `|`. Назви полів (`name:`, `price:` …) не чіпайте.
- Короткі значення — у лапках: `"2 990 грн"`. Лапки всередині тексту — «ялинки» `« »`.
- Збережіть: `Ctrl+S`.

Файл автоматично перевіряється на Railway (крок 6). Перевірити його ще й на комп'ютері — див. `README.md`,
розділ «Запуск на комп'ютері».

## Крок 3. Створіть бота в Telegram (5 хв)

- [ ] У Telegram відкрийте **@BotFather** → **Start** → надішліть `/newbot`.
- [ ] Назва для людей: наприклад, `Для рішучих`.
- [ ] Username латиницею, що закінчується на `bot`: наприклад, `dlya_rishuchyh_bot`.
- [ ] BotFather надішле **токен** (рядок виду `123456789:AAH…`). Збережіть його в надійному місці.
      ⚠️ Нікому не надсилайте токен (і в чат з Claude теж) — це пароль від бота.
- [ ] Необов'язково: `/setuserpic` — аватар, `/setdescription` — текст, який видно до натискання Start,
      `/setabouttext` — опис у профілі бота.

## Крок 5. Створіть сервіс на Railway (5 хв)

- [ ] railway.com → **Login** → **Continue with GitHub**.
- [ ] **New Project** → **Deploy from GitHub repo** → виберіть `tg-bot-dlya-rishuchih`.
      Якщо його немає у списку — **Configure GitHub App** і дозвольте доступ до цього репозиторію.
- [ ] Railway почне збірку (2–4 хв). Помилка «BOT_TOKEN не задано» після першого запуску — **це нормально**.

---

## Крок 6. Токен і постійний диск (5 хв)

- [ ] Сервіс → вкладка **Variables** → **New Variable**: Name `BOT_TOKEN`, Value — токен із кроку 3 →
      **Add** → **Deploy**.
- [ ] **Постійний диск — обов'язково:** `Ctrl+K` (на Mac `⌘K`) → введіть `Volume` → **New Volume** →
      виберіть сервіс бота → **Mount Path**: `/data` → **Create** → **Deploy**.
      Без диска після кожного оновлення бот «забуде» людей, і таймери почнуться заново.
- [ ] Якщо збірка впала: **Deployments** → **View logs** → **Build**. Там список помилок у `content.yaml`
      (яке поле і що не так). Виправте файл на GitHub (крок 10) — Railway перезбере бота сам.

---

## Крок 7. Тариф і налаштування (5 хв)

- [ ] Пробного періоду Railway ($5 разово, 30 днів) вистачить для перевірки. Для постійної роботи
      перейдіть на план **Hobby** ($5 на місяць) у налаштуваннях акаунта Railway (розділ з планами й оплатою)
      і додайте картку. Безкоштовного плану ($1 на місяць) для цілодобової роботи не вистачить.
- [ ] Після переходу на Hobby: сервіс → **Settings** → **Restart Policy** → **Always**.
- [ ] Там само перевірте: **Serverless** вимкнено, **Replicas** = 1 (так за замовчуванням).

---

## Крок 8. Перевірте, що все працює (15 хв + очікування)

- [ ] **Deployments** → **View logs**: має бути `Бот @… запущено. База даних: /data/bot.db` і `Start polling`.
      Попередження «…БЕЗ постійного диска…» бути **не** повинно (якщо є — повторіть крок 6, диск).
- [ ] У Telegram відкрийте свого бота → **Start**: офер із таймером «24 год» і кнопкою «Обрати пакет».
- [ ] «Обрати пакет» → пакет → опис → «Отримати посилання на оплату» → відкрийте посилання:
      чи правильний пакет і сума?
- [ ] Через 2 години має прийти перше нагадування.
- [ ] Перевірка перезапуску: Railway → **Deployments** → ⋮ біля активного деплою → **Restart**.
      Через хвилину надішліть боту `/start` — таймер покаже **той самий** залишок, а не нові 24 години.

> Ваш особистий таймер у боті запускається один раз. Щоб пройти все «з нуля», потрібен інший акаунт Telegram
> (наприклад, телефон колеги).

## Крок 9. Менеджер і статистика (необов'язково, 5 хв)

- [ ] Менеджер відкриває бота, натискає **Start**, потім надсилає `/myid` — бот відповість числом.
- [ ] Ви теж надішліть боту `/myid` — отримаєте своє число.
- [ ] Railway → **Variables**: `MANAGER_CHAT_ID` = число менеджера, `ADMIN_IDS` = ваше число → **Deploy**.
- [ ] Тепер менеджер отримує «💳 Запит посилання на оплату» з іменем людини і пакетом, а вам доступна
      команда `/stats` (скільки людей, хто що відкривав, запити посилань).

## Крок 10. Запуск і щоденна робота

- **Посилання на бота** для реклами: `t.me/ваш_бот`. Для різних каналів — `t.me/ваш_бот?start=instagram`,
  `t.me/ваш_бот?start=tiktok`: команда `/stats` покаже, звідки прийшли люди.
- **Змінити тексти, ціни, посилання, нагадування:** GitHub → репозиторій → `content.yaml` → ✏️ (**Edit**) →
  зміни → **Commit changes**. За 2–4 хв Railway запустить нову версію; таймери людей не скидаються.
  Якщо у файлі помилка, нова версія не запуститься, а стара працюватиме далі; помилки — у журналі збірки.
- **Оплати:** бот оплату не перевіряє. Менеджер бачить оплати у платіжній системі, людина надсилає квитанцію,
  менеджер видає доступ до курсу вручну.
- **Не запускайте** бота на комп'ютері з тим самим токеном, поки він працює на Railway: дві копії конфліктують.
- **Щось не так** — розділ «Типові проблеми» в [`DEPLOY.md`](DEPLOY.md).
